# Crown — Отложенное

Всё, чего **нет** в доверенном контуре, и почему. Правило: **пока строка здесь — в репах периметра ни
строчки кода, ни хука, ни поля конфига под неё.** «Подготовить место» — запрещённая спекулятивная
обобщённость (`01-standards`). Реализовал — заводи отдельный реп, строку отсюда удаляй.

## Отдельные продукты (свои репы)

| Что | Почему не периметр | Шов |
|---|---|---|
| **crown-app** (`web`/`api`/`moderation`/`mirror`) | косметика, ключи, показ; денег/репутации на клиенте нет | читает открытую книгу; порождает честные сеттлменты; скрининг на входе (см. ниже) |
| **crown-ops** | деплой, циклы, reproducible build, blackhole | операционные средства и ключи; периметра не касается |
| **Новые игры** | свои эскроу-параметры, резолвер, комиссия | форма `crown-factory` + строка allowlist релея; ноль касаний периметра |

## Потоки денег · non-custodial · скрининг

Куда деньги приходят **к платформе**: только **3% комиссии её собственных игр** (`fee_wallet` вшит в
эскроу при рождении). Сплиттер — ноль баланса; чтение книги — бесплатно; пошлины — циклы канистры, не
выручка. **Через книгу к платформе деньги не приходят вообще.**

- Прямой донат → получателю целиком, платформе **$0**.
- Чужая игра / тулза поверх открытой книги → комиссия ей, платформе **$0**.
- **Своя игра** → 3% (единственная точка, где чужой доллар касается платформы).

**Периметр non-custodial и нейтрален** (как платёжный рельс) — фильтровать не может и не должен.
**Скрининг (KYC/AML/санкции/OFAC + модерация контента) — задача прикладного слоя `crown-app`**, на
входе, до создания транзакции в своих играх. «Брать/не брать и как скринить» — юридически-бизнесовое
решение (с юристом), не код периметра.

## Решения, а не код (с триггерами)

| Что | Триггер |
|---|---|
| Юрисдикция инкорпорации, допуск юзеров (США), AML/санкции без KYC | до mainnet (P8), с юристом |
| Механизм пополнения циклов (операционные средства → cycles заблэкхоленного индекса) | **до** снятия контроллера (P8); порядок необратим |
| Живое управление allowlist релея / автопополнение бюджета из комиссий | когда список меняется часто |
| Суточный бюджет голосов на канистру игры (сверх `V_MAX`) | если per-scope `V_MAX` окажется мало |
| Склейка личностей поверх кошельков | отображение показывает рядом; **книга не узнаёт никогда** |
| Вход средств из других сетей (CCTP → нативный USDC на кошелёк, дальше обычный донат) | слой `crown-app`, вне контура; подключается в любой момент |
| Сплиттеры/формы на других сетях, новая форма эскроу | новая фабрика = новое поколение индекса (`00 §8`); решение до заморозки |
| Игра-потребитель формы `payout-table` (форма — в наборе `crown-factory`, замораживается по `00 §8`) | когда появится use-case, **возможно post-mainnet**; на готовой форме — ноль касаний периметра, лишь строка allowlist релея |
| D5: микро-донаты ниже флора впись-репутации | только если батчить и чтения индекса; отложено |

## Что сломается первым (и почему это нормально)

- `recertify`/состояние на объёме → keyed-Merkle O(log n) + прунинг; книга derived → битая канистра
  заменяется новым поколением.
- Дрейф цены RPC выше запаса `INGEST_PRICE` → ловит cost-gate до заморозки; после — новое поколение.
- Плата IC за чтения (макро) → boundary rate-limit + бюджет; вне контроля.

Актив — пара **(адреса периметра, история чейна)**, а не канистра. Поэтому заморозка дёшева, а всё
косметическое и рискованное живёт снаружи и меняется свободно.
