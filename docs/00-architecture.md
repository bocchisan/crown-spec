# Crown — Архитектура

**Единый источник устройства системы. Читать перед всем остальным.**

Система — пять артефактов и один закон. Всё дорогое оплачено, всё состояние производно, безопасность
денег ончейн. Ничего сверх этого. Каждый компонент — один и тот же паттерн (§3) в разных одеждах.

---

## 1. Артефакты

| Артефакт | Где | Держит деньги | Держит ключи | После заморозки |
|---|---|---|---|---|
| `splitter` | Solana | нет, никогда | нет | immutable |
| `factory` + `escrow` (3 формы) | Solana | эскроу — до расчёта | нет | immutable |
| `indexer` | канистра ICP | нет | нет | blackholed |
| `game` × N | канистра ICP | нет | per-scope threshold | свободна |
| `relay` | канистра ICP | бюджет циклов | нет | не заморожен (управляется) |

Доверенный периметр — `splitter` + `factory`: пиннуты, immutable, денег не держат, врать не могут.
Остальное либо derived (`indexer`), либо не влияет на книгу (`game`, `relay`), либо non-custodial
(эскроу держит до расчёта, адрес вычисляется). Между `splitter`, `factory` и `indexer` каналов нет —
индекс читает их из публичного чейна.

---

## 2. Закон

Книга — отображение `(chain, donor, recipient) → Σ gross`; `gross` в USDC minor units (6 знаков), `u128`.

```
reduce(book, Settled{chain, donor, recipient, gross}) = book[key] = book[key].checked_add(gross)?
```

Одно правило, одна ветка. Репутация ≡ честно уплаченный доллар, дошедший до получателя через
`splitter` и **оплаченно включённый** в книгу. Линейно, монотонно, непередаваемо, per-wallet, локально
получателю. Без дельт, дебета, decay, возврата. Потеря ключей = потеря репутации (свойство, не баг).

Свёртка `reduce` — чистая, детерминированная, zero-dep функция. Доказуемые свойства (тесты):
монотонность, аддитивность (нечувствительность к порядку), пересчёт (`book[k] == Σ gross`), изоляция
ключа, детерминизм. Ключ включает `chain`: кластеры — разные вселенные, записи не смешиваются.

## 3. Единый механизм

Вся система — один паттерн, повторённый в каждой канистре. Это и есть её цельность.

1. **Событийно, не по расписанию.** Ни таймеров, ни поллинга нигде — канистра никогда не будит себя
   сама; работа только по внешнему вызову, который инициирует и оплачивает вызывающий.
2. **Оплачено, и оплата — до работы.** Всякая дорогая операция (RPC-впись, threshold-подпись)
   требует прикреплённых циклов ≥ цены **прежде** исполнения; недоплата reject'ится ценой двух чтений;
   мусор самофинансируется. Ingress не умеет прикреплять циклы → фронтит `relay` (§6). Где оплата не
   применима (ingress игры авторизован подписью кошелька, не циклами), гейтом служит **граница**:
   `inspect_message` доказывает применимость (подпись + пруф) не-реплицируемо, и реплицируемое
   исполнение идёт лишь после — та же герметичность, другим ключом (`games-harness.md` §6).
3. **Состояние производно, материализуется лениво.** Книга — фолд. Вердикт игры — чистая функция
   `f(голоса, deadline, now)`, вычисляемая на чтении/оплаченном вызове. Объект (задача/сбор/лот/
   аукцион) **не хранится**, пока к нему не привязан реальный ончейн-эскроу (пруф рождения, §5).
   Ни одного хранимого байта без ренты за спиной.
4. **Безопасность не зависит от живости.** Ончейн-`refund()` по `deadline` возвращает деньги без
   канистры. Ни одна канистра не обязана проснуться сама; погасни весь ICP — деньги целы на Solana.
5. **Доверие — арифметика.** Признание = пиннутый адрес + деривация PDA. Происхождение/членство =
   свидетель против подписанного корня, проверяемый чистым счётом, **без обращения наружу**.
6. **Один примитив доказательства: подписанный корень + свидетель членства.** Репутация, рождения,
   вердикты — три плоскости, одна форма. Потребитель проверяет свидетель локально против пиннутого
   корня; дорогая операция уходит с анонимного пути.

**Эмиссия репутации оплачена, не бесплатна.** Чтобы сеттлмент попал в книгу, кто-то платит
`INGEST_PRICE` (релеер из 3% комиссий; прямой донор — через свою бюджетную канистру). Это цена
герметичности: неоплаченной работы в системе нет — значит нет и неоплаченного DoS. Чтение книги —
бесплатно (query не тарифицируется).

## 4. Признание и атрибуция

Индекс засчитывает `Settled` **только от пиннутого `splitter`** (адрес из `config/`). Атрибуция донора:

```
sender == splitter                          → donor из события
sender выводится из factory ∈ factories[]   → прочитать donor эскроу (байты 8..40), засчитать ему
иначе                                       → donor как есть
```

Вывод — арифметика: `find_program_address([b"escrow", salt], factory) == sender` через внешний крейт
`crown-derive`; `salt`/`donor` — поля аккаунта, владельцем которого обязана быть фабрика (конвенция
заголовка, `crown-factory/docs/spec.md`). Реестра нет, доверия к событиям нет. Два корня доверия — `splitter` и
`factories[]` — пиннуты в конфиге; что не выводится из них, для книги не существует.

Резолвер игры — **per-scope threshold-ключ** (`derivation_path = [scope_id]`, scope = лот/сбор/задача).
Привязка деньги↔текст↔область — деривация, не реестр.

## 5. Рождения эскроу

Индекс распознаёт рождение по инструкции `create_escrow` пиннутой фабрики, **парся транзакцию**
(`getTransaction`; `slot` — из меты). Хранит `escrow → {donor, slot}` вторым keyed-Merkle-корнем.
`gross` не хранится: атрибуция читает лишь `donor`, а деривация адреса эскроу игрой уже коммитит `gross`
через соль — так распознавание рождения раскладко-независимо (не гадает офсет per-форма). Впись
рождения — платная, как сеттлмент. Прунится по терминальности (`claim`/`refund`).

**Пруф рождения** = свидетель против корня рождений, предъявляемый вызывающим игре и проверяемый
**локально без RPC** (сохраняет слепоту игр, §3.5). Это одновременно триггер материализации объекта
(§3.3) и барьер спама: за каждым хранимым объектом — реальный эскроу с рентой (~$0.35, заперта
навсегда). Асимметрия: атакующему $0.35 за материализацию, защитнику — доля цента.

## 6. Индексатор и релеер

**Индексатор — один, платный.** Ни слепого поллинга, ни будильника, ни сторожа.

- **Ингест:** `ingest(signature)` — единственный не-`query`, платный (`INGEST_PRICE`, проверка оплаты
  до RPC). Распознаёт сеттлменты и рождения, сворачивает, обновляет корни. Exactly-once — набор
  применённых сигнатур; пустые сигнатуры applied **не** помечает; прунится.
- **Корни:** keyed-Merkle по книге и по рождениям; `combined_root` в `set_certified_data`; свидетель
  по ключу — `query`.
- **Query (бесплатны):** `get_reputation`+witness, `get_birth`+witness, `get_certificate`, счётчики.
- **Финальность:** `commitment = finalized`, всегда. Реорг до финальности → события нет в свёртке.
- **Перекрёстная сверка:** каждый `Settled` пиннутого сплиттера сверяется с отдельным исполненным
  `TransferChecked` в той же транзакции (gross/mint/authority=донор); нет пары — не засчитано, инкремент
  аномалий. Репутация ≤ реально сдвинутых денег; аутентичность события даёт program-id сплиттера
  (событие-CPI подделать нельзя), поэтому глубина стека совпадать не обязана.
- **Чейн-чтение** — только через SOL RPC-канистру под NNS, консенсус ≥3 провайдеров; mainnet — только
  `Default`-источники.

**Релеер — единый фронтер оплаченных вызовов** (ingress циклы прикреплять не умеет): форвардит вписи
(сеттлменты + рождения) и запросы подписи игр, прикрепляя циклы из бюджета (3% комиссий). Единственный
не-`query` — `submit`, за allowlist; `inspect_message` отсекает чужих/переростков до исполнения;
per-key rate-limit против утёкшего ключа; пол по бюджету. Не заморожен — им управляют (allowlist,
бюджет, principal индекса). Над книгой не властен: подделать репутацию не может, только оплачивает
фетч. Бэкстоп цензуростойкости: любой со своей бюджетной канистрой платит мимо релеера.

## 7. Потоки

**Прямой донат:** `donor → splitter → recipient` целиком, `emit Settled`. Впись оплачивает релеер/донор.

**Игра (класс B):**
```
game ── create_escrow(resolver=key([scope_id]), params) ──► factory ──► escrow   (donor финансирует)
  settle: первый оплаченный claim ──► игра лениво считает вердикт f(голоса, deadline, now),
          подписывает корень области (оплаченная по требованию через relay); escrow проверяет подпись+путь ──►
          комиссия игры ──► splitter ──► recipient;  emit Settled(donor = escrow)
  refund: после deadline, без подписи, кто угодно ──► donor, 100%.  Settled нет, репутации нет.
```

Голос — self-подпись + пруф веса (свидетель книги), проверяется локально; звонка в индекс нет.
Создание объекта — permissionless no-op (чистая деривация `id`); запись материализуется на первом
эскроу с пруфом рождения. Тайминги/конфиг области — в прообразе `id` (хеш-проверка при материализации);
окно времени якорится на ончейн-`deadline` эскроу.

**Ингест:** `Settled`/рождение в блоке → релеер `submit` (оплачено) → `indexer.ingest` → корни →
`query` (бесплатно, сертифицировано) → кто угодно.

## 8. Заморозка и расширение

Замерзают `splitter`, `factory`, `indexer`. Обоснование — честность закона: замороженные
`reduce`/распознавание нельзя переписать задним числом; независимого verifier-сервиса нет.

- Баг в замороженном индексе неисправим апгрейдом → **новое поколение**: новая канистра пересчитывает
  книгу из чейна с нуля. Актив — пара `(адреса периметра, история чейна)`, не канистра. Заморозка дёшева.
- Новая игра на существующей форме — **ноль касаний периметра** (индекс пиннит фабрику, не игру).
  Предела числу игр нет, апрув не нужен, фабрика stateless/immutable → без контенции.
- Новая форма эскроу = новая фабрика = новый адрес в `factories[]` = новое поколение индекса.
  Замороженный ресурс — **набор форм, не число игр**.

До заморозки: reproducible build (хэш wasm опубликован); cost-gate (замер живых цен → константы с
запасом); выравнивание флоров; per-key cap релея; протестированное пополнение циклов **до** снятия
контроллера (порядок необратим).

## 9. Экономика

- Ядро денег не держит и не зарабатывает. Монетизация — 3% комиссии **своих** игр (снимаются эскроу
  **до** сплиттера, в книгу не попадают). Индекс их не читает — доверяет адресу, не числам.
- **Себестоимость:** фикс ≈ ноль (хранение $5.47/GiB·год, чтения бесплатны, idle-тактов нет);
  переменная ~$0.02/игровой сеттлмент, ~$0.009/прямой; 3% перекрывают ~7× при донате $5. Индекс
  само-окупается на марже `INGEST_PRICE − RPC`. Полная таблица цен и break-even — `crown-indexer/docs/spec.md`.
- Газ Solana — донор (центы). Циклы канистр — оператор (reverse gas): читатель не платит никогда.
  Пополнение заблэкхоленного индекса — permissionless deposit.
- Уйти в минус можно только: утёкший ключ релея (закрывается per-key cap), сабфлор при
  невыровненном флоре (закрывается алайнментом), тонкая заморозка констант (cost-gate с запасом),
  плата IC за чтения (макро, вне контроля). Свободные прямые донаты и сабфлор структурно не
  оплачиваются платформой (эмиссия платная + `MIN_GROSS`).

## 10. Принятые ограничения

1. Самосибил дёшев — книга есть реестр фактов платежей, не анти-сибил; потребитель веса приносит свою защиту.
2. Плутократия by construction — репутация тождественна деньгам.
3. Локальна кластеру — devnet/mainnet разные книги, между ними ничего не переносится.
4. Содержимое — оплаченно-включённое, не всё-чейновое; проверяемо публичным набором сигнатур.
5. Доверие RPC-канистре NNS — сокращение доверия, не его отсутствие.
6. Плата IC за чтения (если введут) — единственный расход вне контроля; митигация — boundary
   rate-limit + бюджет, не код.

## 11. Незыблемые принципы (NEVER)

- Ни одной зависимости в `reduce`. Конверсия — на границе.
- Единственный не-`query` у индекса — платный `ingest`; у релея — `submit`; у игры — фиксированный
  список update. Всё прочее в `.did` — `query`.
- Не засчитывать `Settled` не от пиннутого сплиттера; не атрибутировать не от пиннутой фабрики.
- Ни грамма дорогой работы (RPC, threshold-подпись, перманентная запись) до проверки оплаты/пруфа.
- Игры не ходят наружу: ни SOL RPC, ни звонков в индекс — только проверка пруфов чистым счётом.
- Ни одного хранимого байта без реального эскроу за спиной (ленивое создание).
- Ни таймеров, ни поллинга: pull + ленивый вердикт; safety — ончейн-`refund()`.
- Ядру/играм не держать денег, ключей сверх per-scope резолвера, не резолвить исходы вне подписи.
- Ни дельт/дебета/сгорания/decay. Ни второго перевода/казны в сплиттере. Ноль баланса — инвариант.
- `Custom` RPC-источники — только testnet-профиль. Сетевые значения — только `config/`.
- Ни `unwrap`/`expect`/`panic!`/немаркированной арифметики в `reduce` и на пути ингеста.
- Ни кода «на будущее» без текущего потребителя.

Расхождение кода с этим файлом = баг. Правь код; неверен принцип — сначала правь этот файл, тем же
коммитом.
