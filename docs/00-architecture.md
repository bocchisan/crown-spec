# Crown — Архитектура

**Единый источник устройства системы. Читать перед всем остальным.**

Система — пять артефактов и один закон. Всё дорогое оплачено, всё состояние производно, безопасность
денег ончейн. Ничего сверх этого. Каждый компонент — один и тот же паттерн (§3) в разных одеждах.

---

## 1. Артефакты

| Артефакт | Где | Держит деньги | Держит ключи | После заморозки |
|---|---|---|---|---|
| `splitter` | Solana | нет, никогда | нет | immutable |
| `factory` + `escrow` (2 формы, в mainnet-набор входит одна) | Solana | эскроу — до расчёта | нет | immutable |
| `indexer` | канистра ICP | нет | нет | blackholed |
| `game` × N | канистра ICP | нет | per-scope threshold | свободна |
| `relay` | канистра ICP | бюджет циклов | нет | не заморожен (управляется) |

Доверенный периметр — `splitter` + `factory`: пиннуты, immutable, денег не держат, врать не могут.
Остальное либо derived (`indexer`), либо не влияет на книгу (`game`, `relay`), либо non-custodial
(эскроу держит до расчёта, адрес вычисляется). Между `splitter`, `factory` и `indexer` каналов нет —
индекс читает их из публичного чейна.

---

## 2. Закон

Книга — отображение `(chain, donor, recipient) → Σ gross`; `gross` в USDC minor units (6 знаков), `u128`.

```
reduce(book, Settled{chain, donor, recipient, gross}) = book[key] = book[key].checked_add(gross)?
```

Одно правило, одна ветка. Репутация ≡ честно уплаченный доллар, дошедший до получателя через
`splitter` и **оплаченно включённый** в книгу. Линейно, монотонно, непередаваемо, per-wallet, локально
получателю. Без дельт, дебета, decay, возврата. Потеря ключей = потеря репутации (свойство, не баг).

Свёртка `reduce` — чистая, детерминированная, zero-dep функция. Доказуемые свойства (тесты):
монотонность, аддитивность (нечувствительность к порядку), пересчёт (`book[k] == Σ gross`), изоляция
ключа, детерминизм. Ключ включает `chain`: кластеры — разные вселенные, записи не смешиваются.

## 3. Единый механизм

Вся система — один паттерн, повторённый в каждой канистре. Это и есть её цельность.

1. **Событийно, не по расписанию.** Ни таймеров, ни поллинга нигде — канистра никогда не будит себя
   сама; работа только по внешнему вызову, который инициирует и оплачивает вызывающий.
2. **Оплачено, и оплата — до работы.** Всякая дорогая операция (RPC-впись, threshold-подпись)
   требует прикреплённых циклов ≥ цены **прежде** исполнения; недоплата reject'ится ценой двух чтений;
   мусор самофинансируется. Ingress не умеет прикреплять циклы → фронтит `relay` (§6). Где оплата не
   применима (ingress игры авторизован подписью кошелька, не циклами), гейтом служит **граница**:
   `inspect_message` доказывает применимость (подпись + пруф) не-реплицируемо, и реплицируемое
   исполнение идёт лишь после — та же герметичность, другим ключом (`games-harness.md` §6).
   Граница дёшева не бесплатно: у `inspect_message` бюджет 200M инструкций, а **BLS-пары сертификата
   индекса в него не влезают**. Поэтому доверие к индексу расщеплено: аутентификация корня — разовый
   **платный** `push_root`, а per-caller пруф (рождение, репутация) — обход хеш-дерева против
   кешированного корня, O(log n). Расщепление выровнено во **всех трёх** играх (`P6.6`) и на обоих
   путях (рождение и вес голоса): `certified_root` встречается ровно один раз на игру — в `push_root`,
   что закреплено гейтом CI (`games-harness.md` §6).
3. **Состояние производно, материализуется лениво.** Книга — фолд. Вердикт игры — чистая функция
   `f(голоса, deadline, now)`, вычисляемая на чтении/оплаченном вызове. Объект (задача/сбор/лот/
   аукцион) **не хранится**, пока к нему не привязан реальный ончейн-эскроу (пруф рождения, §5).
   Ни одного хранимого байта без ренты за спиной.
4. **Безопасность не зависит от живости.** Ончейн-`refund()` по `deadline` возвращает деньги без
   канистры. Ни одна канистра не обязана проснуться сама; погасни весь ICP — деньги целы на Solana.
5. **Доверие — арифметика.** Признание = пиннутый адрес + деривация PDA. Происхождение/членство =
   свидетель против подписанного корня, проверяемый чистым счётом, **без обращения наружу**.
6. **Один примитив доказательства: подписанный корень + свидетель членства.** Репутация, рождения,
   вердикты — три плоскости, одна форма. Потребитель проверяет свидетель локально против пиннутого
   корня; дорогая операция уходит с анонимного пути.

**Эмиссия репутации оплачена, не бесплатна.** Чтобы сеттлмент попал в книгу, кто-то платит
`INGEST_PRICE` (релеер из 3% комиссий; прямой донор — через свою бюджетную канистру). Это цена
герметичности: неоплаченной работы в системе нет — значит нет и неоплаченного DoS. Чтение книги —
бесплатно (query не тарифицируется).

## 4. Признание и атрибуция

Индекс засчитывает `Settled` **только от пиннутого `splitter`** (адрес из `config/`). Атрибуция донора —
поиск в **уже записанных рождениях** (§5), не чтение чейна:

```
donor события — эскроу с записанным рождением → donor этого рождения
иначе                                          → donor как есть (прямой донат)
```

Арифметика работает не здесь, а на вписи рождения: `find_program_address([b"escrow", salt], factory)`
через внешний крейт `crown-derive` — гейт распознавания рождения, один раз, на его собственной оплаченной
вписи (§5). На расчёте пересчитывать нечего: эскроу либо уже в дереве рождений, либо нет.

**Состояния аккаунтов индекс не читает вовсе** — `getAccountInfo` в `crown-indexer` не встречается ни
разу, всё берётся из `getTransaction`. Поэтому конвенция, на которую он опирается, ровно одна, и она про
раскладку **инструкции** `create_escrow` (`donor` — слот 0, `escrow` — слот 1, `salt` — первый аргумент):
`crown-factory/docs/spec.md §Конвенция заголовка`, п. 7. Прежняя редакция этого параграфа описывала чтение
полей аккаунта эскроу — механизм, которого в коде нет; расхождение снято на `P7.12` в спеке фабрики и в §5,
но сюда не доехало.

Отсюда же требование порядка «рождение раньше расчёта» (§5): атрибуция видит ровно то, что уже свёрнуто.

Реестра нет, доверия к событиям нет. Два корня доверия — `splitter` и
`factories[]` — пиннуты в конфиге; что не выводится из них, для книги не существует.

Резолвер игры — **per-scope threshold-ключ** (`derivation_path = [scope_id]`, scope = лот/сбор/задача).
Привязка деньги↔текст↔область — деривация, не реестр.

## 5. Рождения эскроу

Индекс распознаёт рождение по инструкции `create_escrow` пиннутой фабрики, **парся транзакцию**
(`getTransaction`; `slot` — из меты). Хранит `escrow → {donor, slot}` вторым keyed-Merkle-корнем.
`gross` не хранится: атрибуция читает лишь `donor`, а деривация адреса эскроу игрой уже коммитит `gross`
через соль — так распознавание рождения раскладко-независимо (не гадает офсет per-форма). Впись
рождения — платная, как сеттлмент. **Не прунится** — см. §8: прунинг рождений отложен
(`08-deferred.md`), и его отсутствие сейчас несущее — оно и делает недатированный сертификат
безопасным.

**Порядок обязателен: рождение вписывается раньше расчёта.** Иначе сеттлмент засчитывается адресу
эскроу, а не донору, и это **навсегда**: закон только прибавляет, переатрибуции нет. Из двух механизмов
смены поколения (§8) чинит лишь **пересчёт**; **передача** суммирует поколения и переносит неверный ключ
дальше. Слот-порядок его не держит: индекс сворачивает в том порядке, в каком ему подают сигнатуры.
Долгое время его держал **путь расчёта**: `Settled` от эскроу возможен только через `claim(settle)`
формы `two-outcome`, а тот требует подписи резолвера, которая существует лишь после материализации
области на пруфе рождения. Этого больше не достаточно (ниже), и потому порядок стал гейтом вписи.

**Довода про путь расчёта, однако, хватает только на область из одного эскроу (`B=1`), и это надо
читать буквально.** Он говорит «подпись существует после пруфа рождения» — а пруф был предъявлен ровно
один, тот, что материализовал область. У области с `B=N` (`conditional-funding`; в общем случае —
всякая игра, где членство есть деривация резолвера, а не регистрация) вклады со второго по `N`-й в
канистру не приходят вовсе, и **та же одна подпись открывает их все**. Хуже: `claim` permissionless,
поэтому как только вердикт `settle` произнесён, кто угодно одной транзакцией Solana расчитывает чужой
эскроу — и, подав этот расчёт раньше рождения, сжигает репутацию настоящего вкладчика за цену одной
вписи.

**Поэтому порядок держит не соглашение, а сам индекс.** `Settled` от плательщика **вне кривой**
ed25519 — то есть от PDA, приватного ключа для которого не существует, — без записанного рождения не
сворачивается вовсе: `UnknownBirth`, ноль записей, сигнатура остаётся свободной
(`crown-indexer/src/state.rs::attributable`). Предикат — тот же `solana_is_off_curve`, которым
деривация PDA выбирает bump, так что пер-форменного знания в замороженном пути не появляется. Прямой
донат не задет: его платит подписант транзакции, то есть ключ **на** кривой. Тихая вечная ошибка
становится громким транзиентом — впиши рождение и подай ту же сигнатуру снова; расчистка тоже
permissionless, поэтому заложником чужой расчёт не станет. Цена — сеттлмент от бесключевого
плательщика, который **не** наш эскроу (чужая программа, донатящая через сплиттер под PDA-authority),
перестаёт сворачиваться; это осознанно: репутация под ключом, которого ни у кого нет, — не репутация.

**Пруф рождения** = свидетель против корня рождений, предъявляемый вызывающим игре и проверяемый
**локально без RPC** (сохраняет слепоту игр, §3.5). Это одновременно триггер материализации объекта
(§3.3) и барьер спама: за каждым хранимым объектом — реальный эскроу с рентой (~$0.32, из них ~$0.16 невозвратно — разбор ниже).

**Барьер — половина расход, половина оборот капитала.** Рента возвратна **не вся**, и прежняя
формулировка («она возвратна») была неверна в большей своей половине. Донор платит две ренты:
за аккаунт эскроу (2 199 360 лампортов у `two-outcome`) и за vault-ATA (2 039 280). `refund()`
закрывает **только vault** (`drain_to_donor_and_close`) — ATA возвращается донору, а аккаунт формы
не закрывается никогда и его рента **сгорает**. Это не упущение: пока аккаунт жив, `init` по тем же
seeds падает, то есть адрес эскроу одноразов; закрой его — и ту же соль можно отыграть заново, а
рождение перезаписать новым донором (`crown-factory/docs/spec.md §Конвенция заголовка`, п. 5).

Отсюда честный счёт барьера: ≈52% ренты — **невозвратный расход** на каждую материализованную
область, и ≈48% — капитал, запертый на всё окно, не короче `duration + DEADLINE_MARGIN` (3 суток).
В долларах при SOL $74.65 (замер 2026-07-31) это $0.164 сожжённых и $0.152 запертых, всего $0.316;
доли фиксированы протоколом (рента = `(128 + размер) · 6960` лампортов, размеры 188 и 165 байт),
а USD-цена плавает вместе с SOL — считать её надо на день замера, а не помнить числом. Поток `R`
материализаций в секунду стоит противнику `$0.164 · R` безвозвратно **плюс** `$0.152 · R · окно`
запертыми. Первое слагаемое прежняя редакция теряла целиком, поэтому барьер выглядел чисто
ликвидностным и слабее, чем он есть (`cost.md §6` #8).

## 6. Индексатор и релеер

**Индексатор — один, платный.** Ни слепого поллинга, ни будильника, ни сторожа.

- **Ингест:** `ingest(signature)` — единственный не-`query`, платный (`INGEST_PRICE`, проверка оплаты
  до RPC). Распознаёт сеттлменты и рождения, сворачивает, обновляет корни. Exactly-once — набор
  применённых сигнатур; пустые сигнатуры applied **не** помечает. Прунинга нет — ни здесь, ни в
  рождениях (§5): состояние индекса монотонно, и его ёмкость конечна (§8).
- **Провал вписи состояния не меняет — бюджета попыток нет.** Оплата не возвращается (fund-then-fail
  не должен быть дешевле работы, `01-standards §Тесты 4`), но сигнатура остаётся свободной навсегда:
  `applied` — её единственное терминальное состояние. Счётчик попыток здесь был бы **само-лимитом в
  permissionless-коде**: `commitment = finalized` делает ещё-не-финализованную транзакцию неотличимой
  от нечитаемой, поэтому любой мог бы исчерпать бюджет чужой сигнатуры **до** финальности и вычеркнуть
  платёж из книги навсегда, на канистре, которую не починить. Тот же довод, что в §8 про границу
  поколений: `ingest` permissionless-после-оплаты, поэтому «никто не станет» — соглашение, не
  гарантия. Потолок собственных потерь платформы стоит там, где её деньги уходят, — per-key бюджет
  релея в циклах (§6, **не заморожен**); бюджет ретраев — забота подающего, который живёт снаружи.
- **Корни:** keyed-Merkle по книге и по рождениям; `combined_root` в `set_certified_data`; свидетель
  по ключу — `query`.
- **Query (бесплатны):** `get_reputation`+witness, `get_birth`+witness, `get_certificate`, счётчики,
  `get_births_page` (семя преемника), `get_book_page` (книга преемнику) и `get_state_stats` (датчик
  ёмкости) — все три под передачу, §8.
- **Финальность:** `commitment = finalized`, всегда. Реорг до финальности → события нет в свёртке.
- **Перекрёстная сверка:** каждый `Settled` пиннутого сплиттера сверяется с отдельным исполненным
  `TransferChecked` в той же транзакции (gross/mint/authority=донор); нет пары — не засчитано, инкремент
  аномалий. Репутация ≤ реально сдвинутых денег; аутентичность события даёт program-id сплиттера
  (событие-CPI подделать нельзя), поэтому глубина стека совпадать не обязана. Сверка смотрит на
  `gross`/mint/authority, но **не** на `source ≠ destination`: перевод «в себя» SPL считает успешным
  no-op'ом, и inner-инструкция там настоящая. Поэтому самосеттлмент режется структурно в сплиттере
  (`crown-splitter/docs/spec.md §Три гарантии 1`), а не здесь — иначе неравенство было бы ложным.
- **Флор пыли:** сеттлмент с `gross < MIN_GROSS` в книгу не идёт вовсе — он отбрасывается при
  распознавании, до сверки и до свёртки. Пыль не репутация; сверху этот же флор держат игровые
  `MIN_GROSS[game]` (§9, `cost.md §5`).
- **Чейн-чтение** — только через SOL RPC-канистру под NNS, консенсус ≥3 провайдеров; mainnet — только
  `Default`-источники.

**Релеер — единый фронтер оплаченных вызовов** (ingress циклы прикреплять не умеет): форвардит вписи
(сеттлменты + рождения — это один и тот же вызов, что в транзакции, распознаёт индекс), запросы подписи
игр и пуш корня индекса в игру, прикрепляя циклы из бюджета (3% комиссий). Набор вызовов **закрыт
типом** (`GameCall`), а цена есть функция вызова, не аргумент вызывающего: иначе и выбор метода, и
потолок циклов на вызов уехали бы наружу, к незамороженным играм. Единственный
не-`query` — `submit`, за allowlist; `inspect_message` отсекает чужих/переростков до исполнения;
per-key бюджет в циклах против утёкшего ключа; пол по бюджету. **Два allowlist'а, не один:** кто
вправе слать (`allowlist` — пушеры) и куда вправе уходить прикреплённые циклы (`games` — целевые
канистры любого игрового вызова, и подписи, и пуша корня; впись всегда идёт на пиннутый индекс). Без второго утёкший ключ увёл бы
бюджет на канистру атакующего; неизвестная цель — `UnknownGame`, пустой набор = все игровые вызовы отклонены
(fail closed). Не заморожен — им управляют (оба allowlist'а, бюджет, principal индекса), причём
конфигурация переигрывается и на `post_upgrade`, иначе апгрейд обнулил бы heap-состояние. Над книгой не
властен: подделать репутацию не может, только оплачивает фетч. Бэкстоп цензуростойкости: любой со своей
бюджетной канистрой платит мимо релеера.

## 7. Потоки

**Прямой донат:** `donor → splitter → recipient` целиком, `emit Settled`. Впись оплачивает релеер/донор.

**Игра (класс B):**
```
game ── create_escrow(resolver=key([scope_id]), params) ──► factory ──► escrow   (donor финансирует)
  settle: первый оплаченный claim ──► игра лениво считает вердикт f(голоса, deadline, now),
          подписывает корень области (оплаченная по требованию через relay); escrow проверяет подпись+путь ──►
          комиссия игры ──► splitter ──► recipient;  emit Settled(donor = escrow)
  refund: после deadline, без подписи, кто угодно ──► donor, 100%.  Settled нет, репутации нет.
```

Голос — self-подпись + пруф веса (свидетель книги), проверяется локально; звонка в индекс нет.
Создание объекта — permissionless no-op (чистая деривация `id`); запись материализуется на первом
эскроу с пруфом рождения. Тайминги/конфиг области — в прообразе `id` (хеш-проверка при материализации);
окно времени якорится на ончейн-`deadline` эскроу.

**Ингест:** `Settled`/рождение в блоке → релеер `submit` (оплачено) → `indexer.ingest` → корни →
`query` (бесплатно, сертифицировано) → кто угодно.

## 8. Заморозка и расширение

Замерзают `splitter`, `factory`, `indexer`. Обоснование — честность закона: замороженные
`reduce`/распознавание нельзя переписать задним числом; независимого verifier-сервиса нет.

- Баг в замороженном индексе неисправим апгрейдом → **новое поколение**: новая канистра пересчитывает
  книгу из чейна с нуля. Актив — пара `(адреса периметра, история чейна)`, не канистра. Заморозка дёшева.

- Новая игра на существующей форме — **ноль касаний периметра** (индекс пиннит фабрику, не игру).
  Предела числу игр нет, апрув не нужен, фабрика stateless/immutable → без контенции.
- Новая форма эскроу = новая фабрика = новый адрес в `factories[]` = новое поколение индекса.
  Замороженный ресурс — **набор форм, не число игр**.

**Два способа сменить поколение.** Различаются тем, что именно сломалось.

| | Пересчёт | Передача |
|---|---|---|
| Когда | баг в логике: книга gen-1 неверна | исчерпание ёмкости или новая фабрика: книга gen-1 верна |
| Как | gen-2 сворачивает историю чейна с нуля | gen-1 держит своё, gen-2 продолжает с границы |
| Книга | gen-2 замещает gen-1 | **сумма** поколений — либо одна книга, если gen-2 поглотила gen-1 (#4) |
| Цена | `g` за каждую транзакцию истории | ноль |

Передача опирается на аддитивность закона (§2): книга — фолд, порядок ей безразличен, поэтому
`Σ поколений` тождественна книге одной канистры. Четыре механизма делают её безопасной, и все обязаны
существовать **до** заморозки — заблэкхоленное поколение не отрастит ни метода, ни константы:

1. **Граница** (`CUTOVER_SLOT`, `config/`) — слот, с которого впись есть мандат следующего поколения.
   `slot ≥` границы отклоняется (`AfterCutover`), состояние не меняется, сигнатура остаётся свободной.
   Без границы один сеттлмент, впиcанный в оба поколения, удваивает репутацию за цену одной вписи;
   `ingest` permissionless-после-оплаты, поэтому «никто не шлёт старое в старую канистру» — не гарантия,
   а соглашение. Граница пиннится cost-gate **консервативно**: канистра обязана дойти до неё, не
   исчерпав память, иначе между её смертью и границей — дыра, которую не закроет ни одно поколение.
2. **Семя рождений** (`get_births_page`) — атрибуция читает `escrow → donor` из рождений (§4), поэтому
   поколение, начатое пустым, засчитает **адресу эскроу**, а не донору, всякий эскроу, рождённый до
   него. Ошибка тихая и вечная. `get_birth` семенем быть не может: он отвечает лишь про уже известный
   эскроу, а преемник их по построению не знает — отсюда перечисление. Семя бесплатно (query) и
   проверяемо постфактум: каждая запись сверяется с сертификатом gen-1 через `get_birth`.
   Срок жизни эскроу сверху не ограничен (`claim` не имеет гейта по дедлайну), поэтому окном по слотам
   семя заменить нельзя — передаётся весь набор рождений.
3. **Датчик ёмкости** (`get_state_stats`) — heap, ключи книги, рождения. Состояние целиком в heap,
   книга монотонна, потолок heap на заблэкхоленной канистре не поднять: исчерпание останавливает книгу
   навсегда. Передача планируется по этим числам — или не планируется вовсе. Переезжать надо
   **заранее**: у забитой канистры может не хватить памяти и на ответ, а нечитаемое gen-1 обращает
   сумму поколений в ничто.
4. **Перечисление книги** (`get_book_page`) — то же, что семя, но для книги, и по тому же доводу:
   `get_reputation` отвечает лишь про уже известный `(chain, donor, recipient)`, а преемник по
   построению не знает ни одного. В отличие от семени, обязательным его делает не корректность, а
   **цена владения**: сумма поколений верна и без него, но тогда gen-1 обязана жить и оставаться
   читаемой вечно (см. п. 3), а читатель после `n` переездов опрашивает `n+1` канистр. С перечислением
   gen-2 **поглощает** gen-1: сворачивает выданные страницы (лист книги — накопленный итог, а закон —
   сумма, поэтому один фолд на запись воспроизводит лист точно) и проверяет копию одним сравнением —
   пересобранный корень обязан совпасть с тем, что коммитит сертификат gen-1. Одна проверка на всё
   состояние вместо свидетеля на запись или оплаченного чтения чейна на транзакцию. После этого gen-1
   одноразова и гасится. Поглощение верно ровно тогда, когда верна книга gen-1: копия наследует
   распознавание дословно, поэтому баг чинит только пересчёт.

**Симметричное требование к gen-2, у которого нет носителя в gen-1.** Граница односторонняя: она
запрещает **старой** канистре принимать новое. Обратного запрета — новой принимать старое — в gen-1 нет
и быть не может, он принадлежит преемнику. Без него сумма поколений двоится: сеттлмент из слота до
границы, уже свёрнутый в gen-1, вписывается ещё и в gen-2 за одну впись, и в сумме считается дважды —
тот же довод, что и у самой границы («permissionless-после-оплаты, поэтому "никто не станет" —
соглашение, не гарантия»). Значит **gen-2 обязана отклонять `slot <` границы gen-1**, а поглотившая
gen-1 (#4) — отклонять всё, что уже поглощено. Кода под это сегодня нет и быть не должно: gen-2 не
существует, а когда её пишут, она не заморожена и получает это условие тогда же. Здесь оно записано
затем, что переезд случится годы спустя и другими руками, а отказ тихий — книга просто начинает врать
в большую сторону.

Ёмкость поколения конечна и от нагрузки не зависит — нагрузка задаёт лишь скорость расхода
(`crown-indexer/docs/spec.md §Ёмкость`). Прунинг рождений/`applied` её бы растянул, но он отложен
(`08-deferred.md`): терминальность зависит от формы, а спруненное живое рождение — навсегда потерянная
атрибуция (§5). Передача — механизм, работающий и **без** прунинга; прунинг лишь снижает её частоту.

До заморозки: reproducible build (хэш wasm опубликован); cost-gate (замер живых цен → константы с
запасом); выравнивание флоров; per-key cap релея; протестированное пополнение циклов **до** снятия
контроллера (порядок необратим).

## 9. Экономика

- Ядро денег не держит и не зарабатывает. Монетизация — комиссия **своих** игр: **3%** у эскроу-игр
  (снимается эскроу **до** сплиттера) и **2%** у `direct-settlement` (снимается отдельным переводом в
  той же транзакции, тоже мимо сплиттера). В книгу комиссия не попадает ни там, ни там — что и
  означает «репутация начисляется с `net`». Индекс её не читает — доверяет адресу, не числам.
- **Себестоимость:** фикс ≈ ноль (хранение $5.47/GiB·год, чтения бесплатны, idle-тактов нет);
  переменная **$0.055/игровой сеттлмент** (задание: две вписи $0.019 + подпись $0.036) и **$0.010** на
  прямой донат — замер `P7.22`. 3% покрывают её при `gross ≥ $1.83`, отсюда и флор эскроу-игр; у
  прямого доната та же арифметика при своей комиссии даёт `$0.010 / 0.02 = $0.48` и флор $0.58. Индекс
  само-окупается на марже `INGEST_PRICE − RPC` ($0.023 − $0.010). Полная таблица цен и break-even —
  `cost.md`, конфиги — `config/mainnet.toml` каждого репа.
- Газ Solana — донор (центы). Циклы канистр — оператор (reverse gas): читатель не платит никогда.
  Пополнение заблэкхоленного индекса — permissionless deposit.
- Уйти в минус можно только: утёкший ключ релея (закрывается per-key cap), сабфлор при
  невыровненном флоре (закрывается алайнментом), тонкая заморозка констант (cost-gate с запасом),
  плата IC за чтения (макро, вне контроля). Свободные прямые донаты и сабфлор структурно не
  оплачиваются платформой (эмиссия платная + `MIN_GROSS`); у `direct-settlement` это правило и есть
  сама игра — впись покупается только под донат, который уже заплатил комиссию.

## 10. Принятые ограничения

1. Самосибил дёшев — книга есть реестр фактов платежей, не анти-сибил. Вес голоса — репутация
   голосующего *у получателя*, а она покупается прямым донатом на свой же второй кошелёк: сплиттер
   режет лишь совпадение ATA, так что цена веса ≈ оборот суммы (деньги остаются свои) плюс `INGEST_PRICE`
   ≈ $0.023 за впись (`cost.md §1`). Самодонат и самоголосование поэтому **допустимы by design**, а не пропущены.

   **Отсюда — что такое голосование игры: социальный механизм, а не экономическая гарантия. Решено
   2026-08-02; это ответ, а не отложенный вопрос.** Числа (`quorum_weight`, `approval_threshold`,
   `MIN_VOTE_WEIGHT`) не претендуют стоять против цены покупки веса и остаются такими, какие есть.
   Вариант «поднять их до стоимости атаки» рассмотрен и отклонён: при этом пункте и при §10.2
   у него нет потолка — любое число покупается за свой же оборот плюс пошлину, поэтому «правильного»
   значения не существует, а видимость защиты хуже её отсутствия.

   **Деньги охраняет не голосование, а форма.** Ончейн-`refund()` permissionless после `deadline`,
   отдаёт 100% донору/вкладчику и работает при лежащей канистре, невзятом резолвере и молчащем
   голосовании (`crown-factory/docs/spec.md`, обязательное требование формы). Это гарантия периметра,
   и она не социальная. Голосование лишь распределяет исход **раньше** дедлайна.

   Обязанность, которая отсюда следует и подлежит проверке: спека каждой игры и витрина (`crown-app`,
   `08-deferred.md`) пишут это прямым текстом. Умолчать — единственный неверный вариант: тогда
   пользователь считает голосование защитой, которой оно не является.
2. Плутократия by construction — репутация тождественна деньгам.
3. Локальна кластеру — devnet/mainnet разные книги, между ними ничего не переносится.
4. Содержимое — оплаченно-включённое, не всё-чейновое; проверяемо публичным набором сигнатур.
5. Доверие RPC-канистре NNS — сокращение доверия, не его отсутствие.
6. Плата IC за чтения (если введут) — единственный расход вне контроля; митигация — boundary
   rate-limit + бюджет, не код.

## 11. Незыблемые принципы (NEVER)

- Ни одной зависимости в `reduce`. Конверсия — на границе.
- Единственный не-`query` у индекса — платный `ingest`; у релея — `submit`; у игры — фиксированный
  список update, заданный её спекой. Всё прочее в `.did` — `query`.
- Не засчитывать `Settled` не от пиннутого сплиттера; не атрибутировать не от пиннутой фабрики.
- Ни грамма дорогой работы (RPC, threshold-подпись, перманентная запись) до проверки оплаты/пруфа.
- Игры не ходят наружу: ни SOL RPC, ни звонков в индекс — только проверка пруфов чистым счётом.
- Ни одного хранимого байта без реального эскроу за спиной (ленивое создание).
- Ни таймеров, ни поллинга: pull + ленивый вердикт; safety — ончейн-`refund()`.
- Ядру/играм не держать денег, ключей сверх per-scope резолвера, не резолвить исходы вне подписи.
- Ни дельт/дебета/сгорания/decay. Ни второго перевода/казны в сплиттере. Ноль баланса — инвариант.
- RPC-источник — всегда `Default(cluster)`: `Custom` не выразим типом (`crown-indexer/src/rpc.rs`),
  URL'ов в конфиге нет. Сетевые значения — только `config/` (канистры) / `deploy/` (Solana).
- Ни `unwrap`/`expect`/`panic!`/немаркированной арифметики в `reduce` и на пути ингеста.
- Ни кода «на будущее» без текущего потребителя.

Расхождение кода с этим файлом = баг. Правь код; неверен принцип — сначала правь этот файл, тем же
коммитом.
